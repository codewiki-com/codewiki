Jetpack Compose is the core of Android's modern declarative UI framework. This article will focus on the most fundamental and important concepts of Compose: Composable functions, state management (remember and mutableStateOf), and the Recomposition mechanism, helping beginners build the correct mental model.

## Concept Explanation

### What is Jetpack Compose

Jetpack Compose is Android's native UI development toolkit officially released by Google in 2021. It adopts a **declarative programming paradigm**, allowing developers to build interfaces by describing "what the UI should look like" rather than the traditional "how to build the UI step by step."

**Declarative vs Imperative Comparison**

```kotlin
// Imperative UI (Traditional View System)
// Tell the system "how to do it"
val textView = findViewById<TextView>(R.id.counter)
button.setOnClickListener {
    count++
    textView.text = "Click count: $count"
}

// Declarative UI (Compose)
// Tell the system "what it is"
@Composable
fun Counter() {
    var count by remember { mutableStateOf(0) }

    Column {
        Text("Click count: $count")
        Button(onClick = { count++ }) {
            Text("Click")
        }
    }
}
```

### Problems Compose Solves

1. **Separation between XML and Kotlin**: Traditional development requires switching between XML layouts and Kotlin code
2. **Difficulty in View state synchronization**: Manually updating views is prone to state inconsistency bugs
3. **Difficulty in code reuse**: Custom Views require a lot of boilerplate code
4. **Poor preview experience**: XML preview may differ from runtime behavior

### Core Terminology

| Term | Definition |
|------|------|
| **Composable** | A function annotated with @Composable, the basic building block for constructing UI |
| **State** | Data that drives UI display; state changes trigger UI updates |
| **Recomposition** | The process where Compose re-executes Composable functions to update UI when state changes |
| **remember** | A mechanism to preserve data across recompositions |
| **mutableStateOf** | A function that creates observable state; state changes automatically trigger recomposition |

## Core Principles

### The Nature of @Composable Annotation

The `@Composable` annotation is a marker for the Compose compiler plugin. When the compiler sees this annotation, it performs special processing on the function:

```kotlin
// Code written by developers
@Composable
fun Greeting(name: String) {
    Text(text = "Hello, $name!")
}

// Code actually generated by compiler (simplified illustration)
fun Greeting(name: String, $composer: Composer, $changed: Int) {
    $composer.startRestartGroup(...)

    if ($changed and 0b0001 != 0 || !$composer.skipping) {
        Text(text = "Hello, $name!", $composer, ...)
    } else {
        $composer.skipToGroupEnd()
    }

    $composer.endRestartGroup()?.updateScope { ... }
}
```

The compiler plugin mainly does the following:

1. **Injects Composer parameter**: Every Composable function gets a Composer object injected
2. **Adds position information**: Used to track the Composable's position in the composition tree
3. **Generates recomposition logic**: Determines when to skip execution and when to re-execute

### Composition Process

```
Initial Composition
         ↓
    Execute Composable functions
         ↓
    Build UI tree structure
         ↓
    Render to screen
         ↓
    State changes
         ↓
Recomposition
         ↓
    Only re-execute affected Composables
         ↓
    Update corresponding parts of UI tree
         ↓
    Render changed parts
```

### How remember Works

`remember` creates a "slot" in the composition to store data:

```kotlin
@Composable
fun Counter() {
    // remember creates a slot to store count
    // During recomposition, Compose reads the previous value from the same slot
    var count by remember { mutableStateOf(0) }

    Button(onClick = { count++ }) {
        Text("Count: $count")
    }
}
```

**Internal Mechanism**:

1. **First composition**: Executes the lambda expression, stores the result in the slot
2. **Subsequent recompositions**: Reads value directly from the slot, skips lambda execution
3. **Composition destruction**: Slot and its data are cleared

### mutableStateOf and State Subscription

`mutableStateOf` returns a `MutableState<T>` object, which is an observable state container:

```kotlin
// Simplified implementation principle of mutableStateOf
class MutableStateImpl<T>(value: T) : MutableState<T> {
    private var _value: T = value

    override var value: T
        get() {
            // On read: record current Composable as subscriber
            Composer.current?.recordRead(this)
            return _value
        }
        set(newValue) {
            if (_value != newValue) {
                _value = newValue
                // On write: notify all subscribers that recomposition is needed
                notifySubscribers()
            }
        }
}
```

### Triggering and Scope of Recomposition

```kotlin
@Composable
fun ParentScreen() {
    var name by remember { mutableStateOf("Android") }

    Column {
        // When name changes, only Greeting will recompose
        // Header doesn't depend on name, won't recompose
        Header()
        Greeting(name = name)
        Button(onClick = { name = "Compose" }) {
            Text("Change Name")
        }
    }
}

@Composable
fun Header() {
    // This function won't recompose when name changes
    Text("Welcome Page")
}

@Composable
fun Greeting(name: String) {
    // This function will recompose due to parameter change
    Text("Hello, $name!")
}
```

**Rules for Determining Recomposition Scope**:

1. Composables that read state are marked for recomposition
2. Composables whose parameters change will recompose
3. The Compose compiler automatically determines the minimum recomposition scope

## Key Points

### Characteristics of Composable Functions

```kotlin
// Composable functions can have parameters
@Composable
fun UserProfile(name: String, age: Int) { ... }

// Composable functions can have default parameters
@Composable
fun Button(
    text: String,
    enabled: Boolean = true,
    onClick: () -> Unit = {}
) { ... }

// Composable functions don't return UI, they "emit" UI
@Composable
fun Greeting(name: String) {
    Text("Hello, $name!")  // Emits Text to composition
}

// Composable functions should not have side effects (executed directly in function body)
@Composable
fun BadExample() {
    println("This is a side effect!")  // Avoid this
    saveToDatabase()  // Avoid this
}
```

### Three Elements of State Management

```kotlin
@Composable
fun StateDemo() {
    // Element 1: mutableStateOf - creates observable state
    // Element 2: remember - preserves state across recompositions
    // Element 3: by delegation - simplifies state read/write syntax
    var text by remember { mutableStateOf("") }

    TextField(
        value = text,
        onValueChange = { text = it }
    )
}
```

### State Hoisting

```kotlin
// Stateless Composable (recommended)
@Composable
fun Counter(
    count: Int,
    onIncrement: () -> Unit
) {
    Button(onClick = onIncrement) {
        Text("Count: $count")
    }
}

// Stateful container
@Composable
fun CounterScreen() {
    var count by remember { mutableStateOf(0) }

    Counter(
        count = count,
        onIncrement = { count++ }
    )
}
```

### Variants of remember

```kotlin
@Composable
fun RememberVariants(userId: String) {
    // Basic remember: stays unchanged during composition
    val formatter = remember { DateFormatter() }

    // remember with key: recalculates when key changes
    val user = remember(userId) { loadUser(userId) }

    // rememberSaveable: persists after configuration changes
    var text by rememberSaveable { mutableStateOf("") }

    // rememberCoroutineScope: gets a coroutine scope bound to composition lifecycle
    val scope = rememberCoroutineScope()
}
```

### Example 4: Derived State

```kotlin
@Composable
fun ShoppingCart() {
    // Original state: product list
    var items by remember {
        mutableStateOf(
            listOf(
                CartItem("Apple", 5.0, 2),
                CartItem("Banana", 3.0, 3),
                CartItem("Orange", 4.0, 1)
            )
        )
    }

    // Derived state: use derivedStateOf to avoid unnecessary recomposition
    val totalPrice by remember {
        derivedStateOf {
            items.sumOf { it.price * it.quantity }
        }
    }

    val totalItems by remember {
        derivedStateOf {
            items.sumOf { it.quantity }
        }
    }

    Column(modifier = Modifier.padding(16.dp)) {
        items.forEach { item ->
            CartItemRow(
                item = item,
                onQuantityChange = { newQty ->
                    items = items.map {
                        if (it.name == item.name) it.copy(quantity = newQty)
                        else it
                    }
                }
            )
        }

        Divider(modifier = Modifier.padding(vertical = 8.dp))

        Text("Total items: $totalItems")
        Text(
            text = "Total: ${"%.2f".format(totalPrice)}",
            style = MaterialTheme.typography.titleLarge
        )
    }
}

data class CartItem(
    val name: String,
    val price: Double,
    val quantity: Int
)

@Composable
fun CartItemRow(
    item: CartItem,
    onQuantityChange: (Int) -> Unit
) {
    Row(
        modifier = Modifier
            .fillMaxWidth()
            .padding(vertical = 4.dp),
        horizontalArrangement = Arrangement.SpaceBetween,
        verticalAlignment = Alignment.CenterVertically
    ) {
        Text(item.name)

        Row(verticalAlignment = Alignment.CenterVertically) {
            IconButton(onClick = {
                if (item.quantity > 0) onQuantityChange(item.quantity - 1)
            }) {
                Text("-")
            }
            Text("${item.quantity}")
            IconButton(onClick = { onQuantityChange(item.quantity + 1) }) {
                Text("+")
            }
        }

        Text("${"%.2f".format(item.price * item.quantity)}")
    }
}
```

## Best Practices

### Keep Composable Functions Simple and Pure

```kotlin
// Good practice: pure UI description
@Composable
fun UserCard(user: User, onEdit: () -> Unit) {
    Card {
        Text(user.name)
        Button(onClick = onEdit) {
            Text("Edit")
        }
    }
}

// Avoid: executing side effects in Composable
@Composable
fun BadUserCard(userId: String) {
    val user = fetchUserFromNetwork(userId)  // Direct network request
    saveToAnalytics("user_viewed")  // Direct write
    Card {
        Text(user.name)
    }
}
```

### Use remember Correctly

```kotlin
// Use remember to cache expensive calculations
@Composable
fun ExpensiveCalculation(numbers: List<Int>) {
    val result = remember(numbers) {
        numbers.map { it * it }.sum()  // Only recalculates when numbers change
    }
    Text("Result: $result")
}

// Don't overuse remember
@Composable
fun SimpleText(text: String) {
    // No need to remember simple string operations
    val upperText = remember(text) { text.uppercase() }  // Over-optimization
    Text(upperText)
}
```

### Hoist State to the Appropriate Level

```kotlin
// Hoist state to the nearest common ancestor that needs sharing
@Composable
fun SearchScreen() {
    var query by remember { mutableStateOf("") }

    Column {
        SearchBar(
            query = query,
            onQueryChange = { query = it }
        )
        SearchResults(query = query)
    }
}

// Hoisting state too high causes unnecessary recomposition
@Composable
fun App() {
    var searchQuery by remember { mutableStateOf("") }  // Only used by SearchScreen

    // The entire App will recompose due to searchQuery changes
    NavHost(...) { ... }
}
```

### Use Immutable Data

```kotlin
// Use immutable List, update by creating new List
@Composable
fun TodoList() {
    var todos by remember { mutableStateOf(listOf<Todo>()) }

    Button(onClick = {
        todos = todos + Todo("New Item")  // Creates new List
    }) {
        Text("Add")
    }
}

// Avoid modifying mutable collections
@Composable
fun BadTodoList() {
    val todos = remember { mutableListOf<Todo>() }

    Button(onClick = {
        todos.add(Todo("New Item"))  // Won't trigger recomposition!
    }) {
        Text("Add")
    }
}
```

### Composable Function Naming Conventions

```kotlin
// Use PascalCase for Composables
@Composable
fun UserProfile() { ... }

@Composable
fun NavigationDrawer() { ... }

// Composables that return values use lowercase start (like remember series)
@Composable
fun rememberScrollState(): ScrollState { ... }

// Don't use lowercase start for Composables that emit UI
@Composable
fun userProfile() { ... }  // Wrong
```

## Common Pitfalls

### Pitfall 1: Using Mutable Objects Directly in Composable

```kotlin
// Wrong: directly modifying mutable object won't trigger recomposition
@Composable
fun BrokenCounter() {
    val count = remember { mutableListOf(0) }

    Button(onClick = {
        count[0]++  // Modified value, but won't trigger recomposition
    }) {
        Text("Count: ${count[0]}")
    }
}

// Correct: use mutableStateOf
@Composable
fun WorkingCounter() {
    var count by remember { mutableStateOf(0) }

    Button(onClick = { count++ }) {
        Text("Count: $count")
    }
}
```

### Pitfall 2: Using Unstable Keys in remember

```kotlin
// Wrong: creating new List as key every recomposition
@Composable
fun UnstableRemember(items: List<String>) {
    val processed = remember(items.toList()) {  // toList() creates new instance each time
        items.map { it.uppercase() }
    }
}

// Correct: use items directly (if it's a stable reference)
@Composable
fun StableRemember(items: List<String>) {
    val processed = remember(items) {
        items.map { it.uppercase() }
    }
}
```

### Pitfall 3: Using remember in Conditional Statements

```kotlin
// Wrong: using remember in condition causes state loss
@Composable
fun ConditionalRemember(showAdvanced: Boolean) {
    if (showAdvanced) {
        var advancedSetting by remember { mutableStateOf("") }
        // When showAdvanced becomes false then true again, advancedSetting resets
    }
}

// Correct: move remember outside the condition
@Composable
fun CorrectConditionalRemember(showAdvanced: Boolean) {
    var advancedSetting by remember { mutableStateOf("") }

    if (showAdvanced) {
        TextField(
            value = advancedSetting,
            onValueChange = { advancedSetting = it }
        )
    }
}
```

### Pitfall 4: Forgetting to Use rememberSaveable

```kotlin
// Problem: state lost after screen rotation
@Composable
fun FormWithRemember() {
    var text by remember { mutableStateOf("") }
    // After configuration change (like screen rotation), text resets to empty
}

// Correct: use rememberSaveable to preserve state after configuration changes
@Composable
fun FormWithRememberSaveable() {
    var text by rememberSaveable { mutableStateOf("") }
    // After configuration change, text is still preserved
}
```

### Pitfall 5: Lambda Capturing Stale State

```kotlin
// Wrong: lambda captures stale count value
@Composable
fun StaleClosureCounter() {
    var count by remember { mutableStateOf(0) }

    LaunchedEffect(Unit) {
        delay(3000)
        println("Count: $count")  // Always prints initial value 0
    }
}

// Correct: use rememberUpdatedState to get latest value
@Composable
fun FreshClosureCounter() {
    var count by remember { mutableStateOf(0) }
    val currentCount by rememberUpdatedState(count)

    LaunchedEffect(Unit) {
        delay(3000)
        println("Count: $currentCount")  // Prints latest value
    }
}
```

### Pitfall 6: Executing Time-Consuming Operations in Composable

```kotlin
// Wrong: executing time-consuming operations directly in Composable
@Composable
fun SlowComposable() {
    val data = loadDataFromDatabase()  // Blocks main thread
    Text(data.toString())
}

// Correct: use LaunchedEffect and state
@Composable
fun FastComposable() {
    var data by remember { mutableStateOf<Data?>(null) }

    LaunchedEffect(Unit) {
        data = withContext(Dispatchers.IO) {
            loadDataFromDatabase()
        }
    }

    if (data != null) {
        Text(data.toString())
    } else {
        CircularProgressIndicator()
    }
}
```

## Performance Considerations

### Understanding Smart Recomposition

Compose's compiler automatically optimizes recomposition, but understanding how it works helps write high-performance code:

```kotlin
@Composable
fun OptimizedList(items: List<String>) {
    LazyColumn {
        items(
            items = items,
            key = { it }  // Provide stable keys to help Compose identify items
        ) { item ->
            ListItem(item)
        }
    }
}
```

### Use derivedStateOf to Avoid Unnecessary Recomposition

```kotlin
@Composable
fun SearchResults(items: List<String>) {
    var searchQuery by remember { mutableStateOf("") }

    // Every searchQuery change causes recomposition
    // val filteredItems = items.filter { it.contains(searchQuery) }

    // Only triggers recomposition of dependents when results actually change
    val filteredItems by remember(items) {
        derivedStateOf {
            items.filter { it.contains(searchQuery) }
        }
    }

    TextField(
        value = searchQuery,
        onValueChange = { searchQuery = it }
    )

    LazyColumn {
        items(filteredItems) { item ->
            Text(item)
        }
    }
}
```

### Stability and @Immutable / @Stable Annotations

```kotlin
// Use @Immutable for completely immutable classes
@Immutable
data class User(
    val id: String,
    val name: String,
    val email: String
)

// Use @Stable for classes with stable public properties
@Stable
class UserRepository {
    private var cachedUser: User? = null

    fun getUser(): User? = cachedUser
}

// Compose compiler uses these annotations to optimize recomposition
@Composable
fun UserCard(user: User) {  // User is @Immutable, can safely skip
    Text(user.name)
}
```

### Avoid Creating Lambdas in Loops

```kotlin
// Inefficient: creates new lambda every recomposition
@Composable
fun IneffientList(items: List<String>, onItemClick: (String) -> Unit) {
    Column {
        items.forEach { item ->
            Button(onClick = { onItemClick(item) }) {  // Creates new lambda each recomposition
                Text(item)
            }
        }
    }
}

// Efficient: use remember to cache or use LazyColumn
@Composable
fun EfficientList(items: List<String>, onItemClick: (String) -> Unit) {
    LazyColumn {
        items(items) { item ->
            Button(onClick = { onItemClick(item) }) {
                Text(item)
            }
        }
    }
}
```

### Use Keys Properly

```kotlin
@Composable
fun AnimatedList(items: List<Item>) {
    LazyColumn {
        items(
            items = items,
            // Use stable unique keys instead of indices
            key = { item -> item.id }
        ) { item ->
            AnimatedVisibility(visible = true) {
                ItemRow(item)
            }
        }
    }
}
```

## Practical Scenarios

### Scenario 1: Login Form

```kotlin
@Composable
fun LoginScreen(
    onLoginSuccess: (User) -> Unit
) {
    var email by rememberSaveable { mutableStateOf("") }
    var password by rememberSaveable { mutableStateOf("") }
    var isLoading by remember { mutableStateOf(false) }
    var errorMessage by remember { mutableStateOf<String?>(null) }

    val isFormValid by remember {
        derivedStateOf {
            email.isNotBlank() &&
            password.length >= 6 &&
            android.util.Patterns.EMAIL_ADDRESS.matcher(email).matches()
        }
    }

    val scope = rememberCoroutineScope()

    Column(
        modifier = Modifier
            .fillMaxSize()
            .padding(16.dp),
        verticalArrangement = Arrangement.Center
    ) {
        Text(
            text = "Login",
            style = MaterialTheme.typography.headlineLarge,
            modifier = Modifier.padding(bottom = 32.dp)
        )

        OutlinedTextField(
            value = email,
            onValueChange = {
                email = it
                errorMessage = null
            },
            label = { Text("Email") },
            isError = errorMessage != null,
            modifier = Modifier.fillMaxWidth()
        )

        Spacer(modifier = Modifier.height(8.dp))

        OutlinedTextField(
            value = password,
            onValueChange = {
                password = it
                errorMessage = null
            },
            label = { Text("Password") },
            visualTransformation = PasswordVisualTransformation(),
            isError = errorMessage != null,
            modifier = Modifier.fillMaxWidth()
        )

        errorMessage?.let { error ->
            Text(
                text = error,
                color = MaterialTheme.colorScheme.error,
                modifier = Modifier.padding(top = 8.dp)
            )
        }

        Spacer(modifier = Modifier.height(24.dp))

        Button(
            onClick = {
                scope.launch {
                    isLoading = true
                    try {
                        val user = login(email, password)
                        onLoginSuccess(user)
                    } catch (e: Exception) {
                        errorMessage = "Login failed: ${e.message}"
                    } finally {
                        isLoading = false
                    }
                }
            },
            enabled = isFormValid && !isLoading,
            modifier = Modifier.fillMaxWidth()
        ) {
            if (isLoading) {
                CircularProgressIndicator(
                    modifier = Modifier.size(20.dp),
```

### Scenario 3: Search and Filter

```kotlin
@Composable
fun SearchableList(allItems: List<Product>) {
    var searchQuery by remember { mutableStateOf("") }
    var selectedCategory by remember { mutableStateOf<String?>(null) }

    // Use derivedStateOf to optimize filtering logic
    val filteredItems by remember(allItems) {
        derivedStateOf {
            allItems.filter { product ->
                val matchesSearch = searchQuery.isBlank() ||
                    product.name.contains(searchQuery, ignoreCase = true)
                val matchesCategory = selectedCategory == null ||
                    product.category == selectedCategory
                matchesSearch && matchesCategory
            }
        }
    }

    val categories = remember(allItems) {
        allItems.map { it.category }.distinct()
    }

    Column {
        // Search bar
        OutlinedTextField(
            value = searchQuery,
            onValueChange = { searchQuery = it },
            label = { Text("Search products") },
            leadingIcon = { Icon(Icons.Default.Search, null) },
            modifier = Modifier
                .fillMaxWidth()
                .padding(16.dp)
        )

        // Category filter
        LazyRow(
            contentPadding = PaddingValues(horizontal = 16.dp),
            horizontalArrangement = Arrangement.spacedBy(8.dp)
        ) {
            item {
                FilterChip(
                    selected = selectedCategory == null,
                    onClick = { selectedCategory = null },
                    label = { Text("All") }
                )
            }
            items(categories) { category ->
                FilterChip(
                    selected = selectedCategory == category,
                    onClick = { selectedCategory = category },
                    label = { Text(category) }
                )
            }
        }

        // Results list
        LazyColumn {
            items(
                items = filteredItems,
                key = { it.id }
            ) { product ->
                ProductCard(product)
            }
        }
    }
}
```

## Interview Key Points

### Basic Questions

**Q1: What is the @Composable annotation and what does it do?**

Answer: `@Composable` is a marker annotation used to identify composable functions. The Compose compiler plugin performs special processing on functions marked with `@Composable`:
- Injects Composer parameter to track composition state
- Adds position information to identify location in composition tree
- Generates recomposition logic to support smart UI updates

**Q2: What's the difference between remember and rememberSaveable?**

Answer:
- `remember`: Preserves value during recomposition, but lost after configuration changes (like screen rotation)
- `rememberSaveable`: Value is saved to SavedInstanceState, preserved after configuration changes

**Q3: What does mutableStateOf return? How does it trigger recomposition?**

Answer: `mutableStateOf` returns a `MutableState<T>` object, which is an observable state container. When reading `.value`, Compose records the current Composable as a subscriber; when writing `.value`, it notifies all subscribers that recomposition is needed.

### Advanced Questions

**Q4: What is Recomposition? How does Compose decide which parts need to recompose?**

Answer: Recomposition is the process where Compose re-executes Composable functions to update UI when state changes. Compose uses these strategies to determine recomposition scope:
1. Tracks which states each Composable reads
2. When state changes, only marks Composables that read that state for recomposition
3. Compares Composable parameters; if unchanged and stable type, can skip recomposition
4. Compiler automatically determines minimum recomposition scope (usually lambda boundaries)

**Q5: Why does Compose require Composable functions to be idempotent?**

Answer: Because Compose may call Composable functions at any time, in any order, at any frequency. If functions have side effects or aren't idempotent, it may cause:
- Unpredictable behavior
- UI and data inconsistency
- Performance issues

**Q6: How to optimize Compose performance?**

Answer:
1. Use `remember` to cache calculation results
2. Use `derivedStateOf` to avoid unnecessary recomposition
3. Use `@Stable` or `@Immutable` annotations to help compiler optimize
4. Provide stable keys for list items
5. Hoist state appropriately to the nearest level that needs sharing
6. Avoid executing time-consuming operations in Composables

**Q7: Explain the State Hoisting pattern and its benefits**

Answer: State hoisting is a pattern of extracting state from a Composable to its caller. For example:

```kotlin
// Stateless Composable
@Composable
fun Counter(count: Int, onIncrement: () -> Unit) { ... }

// Stateful container
@Composable
fun CounterScreen() {
    var count by remember { mutableStateOf(0) }
    Counter(count, { count++ })
}
```

Benefits:
- Improves component reusability
- Easier to test (stateless components are easier to test)
- Supports single source of truth principle
- Facilitates state sharing
