Data classes are one of the most distinctive features in the Kotlin language. Through compiler-generated common methods, they significantly reduce boilerplate code, allowing developers to focus on business logic rather than repetitive infrastructure code.

## Concept Explanation

### What is a Data Class

A data class is a class specifically designed by Kotlin for holding data. In traditional object-oriented programming, we often need to create classes primarily used to store data, commonly referred to as "Value Objects," "Data Transfer Objects" (DTOs), or "Entities."

In Java, creating such a simple data container class requires writing a lot of boilerplate code:

```java
// Data class in Java
public class User {
    private final String name;
    private final int age;

    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String getName() { return name; }
    public int getAge() { return age; }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        User user = (User) o;
        return age == user.age && Objects.equals(name, user.name);
    }

    @Override
    public int hashCode() {
        return Objects.hash(name, age);
    }

    @Override
    public String toString() {
        return "User{name='" + name + "', age=" + age + "}";
    }
}
```

In Kotlin, you only need one line of code:

```kotlin
data class User(val name: String, val age: Int)
```

This single line of code causes the compiler to automatically generate:

- `equals()` / `hashCode()` methods
- `toString()` method
- `componentN()` functions (for destructuring declarations)
- `copy()` function (for copying objects with modified properties)

### Historical Background

The design philosophy of data classes originates from immutable data structures and algebraic data types (ADT) in functional programming. Scala has case classes, Haskell has data types, and Java 14 introduced record types - these are all similar concepts.

Kotlin has supported data classes since version 1.0, with continuous enhancements in subsequent versions:

- Kotlin 1.0: Introduced basic data class functionality
- Kotlin 1.1: Support for data classes extending sealed classes
- Kotlin 1.5: Introduced `value class` (inline class) as a supplement
- Kotlin 1.9: Introduced `data object` for singleton data objects

### Problems Solved

1. **Eliminates boilerplate code**: Automatically generates equals, hashCode, toString, and other methods
2. **Ensures consistency**: Compiler-generated methods don't make mistakes and automatically update with property changes
3. **Supports immutability**: Combined with the `val` keyword to achieve truly immutable data
4. **Simplifies copy operations**: The copy() function makes creating modified copies easy
5. **Supports destructuring**: Object properties can be directly unpacked into multiple variables

## Core Principles

### Compiler Generation Mechanism

When the compiler encounters the `data` keyword, it executes the following steps:

1. **Validates constraints**: Checks if the data class meets all requirements
2. **Analyzes primary constructor**: Extracts all property information
3. **Generates methods**: Generates standard methods based on primary constructor parameters

```kotlin
data class Point(val x: Int, val y: Int)

// Code actually generated by the compiler (simplified version)
class Point(val x: Int, val y: Int) {

    override fun equals(other: Any?): Boolean {
        if (this === other) return true
        if (other !is Point) return false
        return x == other.x && y == other.y
    }

    override fun hashCode(): Int {
        var result = x
        result = 31 * result + y
        return result
    }

    override fun toString(): String = "Point(x=$x, y=$y)"

    operator fun component1(): Int = x
    operator fun component2(): Int = y

    fun copy(x: Int = this.x, y: Int = this.y): Point = Point(x, y)
}
```

### Implementation Principles of equals() and hashCode()

The compiler-generated `equals()` method follows these rules:

1. **Identity check**: First checks if it's the same object reference
2. **Type check**: Checks if the parameter is of the same type
3. **Property comparison**: Compares all properties in the primary constructor one by one

```kotlin
data class Person(val name: String, val age: Int)

// Generated equals implementation
override fun equals(other: Any?): Boolean {
    if (this === other) return true                    // Same reference
    if (other !is Person) return false                 // Type check
    return name == other.name && age == other.age      // Property comparison
}
```

The `hashCode()` implementation uses the standard hash code calculation formula:

```kotlin
override fun hashCode(): Int {
    var result = name.hashCode()
    result = 31 * result + age    // 31 is a commonly used prime multiplier
    return result
}
```

Reasons for choosing 31 as the multiplier:

- 31 is an odd prime, reducing hash collisions
- `31 * i` can be optimized to `(i << 5) - i`, providing high computational efficiency

### How componentN() Functions Work

The compiler generates `component1()`, `component2()`, etc., functions in order for each parameter in the primary constructor:

```kotlin
data class Triple(val first: String, val second: Int, val third: Boolean)

// Generated componentN functions
operator fun component1(): String = first
operator fun component2(): Int = second
operator fun component3(): Boolean = third
```

These functions are declared as `operator`, enabling Kotlin to use them in destructuring declarations:

```kotlin
val (a, b, c) = Triple("hello", 42, true)
// Equivalent to:
// val a = triple.component1()
// val b = triple.component2()
// val c = triple.component3()
```

### Implementation Mechanism of copy() Function

The `copy()` function leverages Kotlin's default parameter feature:

```kotlin
data class User(val name: String, val age: Int, val email: String)

// Generated copy function
fun copy(
    name: String = this.name,
    age: Int = this.age,
    email: String = this.email
): User = User(name, age, email)
```

This allows us to selectively modify some properties:

```kotlin
val user = User("John", 25, "john@example.com")
val updated = user.copy(age = 26)  // Only modify age
```

## Key Points

### Data Class Definition Requirements

| Requirement | Description |
|-------------|-------------|
| data keyword | Class declaration must start with `data` |
| Primary constructor | Must have at least one parameter |
| Parameter modifiers | All parameters must be marked with `val` or `var` |
| Class modifier restrictions | Cannot be abstract, open, sealed, or inner |
| Interface implementation | Can implement interfaces |
| Sealed class inheritance | Can extend sealed classes or sealed interfaces |

### Overview of Auto-Generated Methods

| Method | Purpose | Participating Properties |
|--------|---------|-------------------------|
| `equals()` | Structural equality comparison | Primary constructor parameters |
| `hashCode()` | Compute hash code | Primary constructor parameters |
| `toString()` | Generate readable string | Primary constructor parameters |
| `component1()`...`componentN()` | Support destructuring declarations | Primary constructor parameters |
| `copy()` | Create modified copy | Primary constructor parameters |

### Primary Constructor Parameters vs Class Body Properties

Only parameters in the primary constructor participate in auto-generated methods:

```kotlin
data class Employee(val id: Int, val name: String) {
    var department: String = ""        // Does not participate in equals/hashCode
    val joinDate: Long = System.currentTimeMillis()  // Does not participate
}

val e1 = Employee(1, "John").apply { department = "Engineering" }
val e2 = Employee(1, "John").apply { department = "Marketing" }

println(e1 == e2)  // true - department does not participate in comparison
println(e1.copy()) // Employee(id=1, name=John) - department is not copied
```

### Immutability Best Practices

It's recommended to use `val` for all properties to achieve truly immutable data classes:

```kotlin
// Recommended: Immutable data class
data class ImmutableUser(val id: Int, val name: String, val email: String)

// Not recommended: Mutable data class (unless there's a good reason)
data class MutableUser(var id: Int, var name: String, var email: String)
```

```kotlin
data class Order(

    val items: List<String>,
```

### Detailed Destructuring Declarations

```kotlin
data class Student(
    val id: Int,
    val name: String,
    val grade: Int,
    val score: Double
)

fun main() {
    val student = Student(1, "Li Ming", 3, 92.5)

    // Basic destructuring
    val (id, name, grade, score) = student
    println("$name (ID: $id) is in grade $grade with score $score")

    // Use _ to ignore unwanted values
    val (_, studentName, _, studentScore) = student
    println("$studentName's score is $studentScore")

    // Destructuring in lambda
    val students = listOf(
        Student(1, "John", 2, 88.0),
        Student(2, "Jane", 3, 95.0),
        Student(3, "Bob", 2, 76.5)
    )

    // Destructuring in for loop
    for ((_, name, grade, score) in students) {
        println("$name (Grade $grade): $score points")
    }

    // Destructuring in map operation
    val summaries = students.map { (id, name, _, score) ->
        "ID$id-$name: $score"
    }
    println(summaries)
}
```

### Nested Data Classes and Deep Copying

```kotlin
data class Address(
    val street: String,
    val city: String,
    val zipCode: String,
    val country: String = "USA"
)

data class ContactInfo(
    val email: String,
    val phone: String,
    val address: Address
)

data class Customer(
    val id: String,
    val name: String,
    val contact: ContactInfo,
    val vipLevel: Int = 0
)

fun main() {
    val customer = Customer(
        id = "C001",
        name = "John",
        contact = ContactInfo(
            email = "john@example.com",
            phone = "1234567890",
            address = Address(
                street = "123 Main St",
                city = "New York",
                zipCode = "10001"
            )
        )
    )

    // Updating nested properties requires layer-by-layer copy
    val updatedCustomer = customer.copy(
        contact = customer.contact.copy(
            address = customer.contact.address.copy(
                city = "Los Angeles",
                street = "456 Oak Ave",
                zipCode = "90001"
            )
        )
    )

    println("Original customer city: ${customer.contact.address.city}")      // New York
    println("Updated customer city: ${updatedCustomer.contact.address.city}") // Los Angeles

    // Extracting nested information
    val (_, name, contact) = customer
    val (email, phone, address) = contact
    val (street, city, _, country) = address

    println("$name lives at $street, $city, $country")
}
```

### Combining Data Classes with Sealed Classes

```kotlin
sealed class Result<out T> {
    data class Success<T>(val data: T, val message: String = "Operation successful") : Result<T>()
    data class Error(val code: Int, val message: String, val cause: Throwable? = null) : Result<Nothing>()
    data object Loading : Result<Nothing>()
}

// API response model
data class User(val id: Int, val name: String, val email: String)
data class PageInfo(val page: Int, val pageSize: Int, val total: Int)
data class PaginatedData<T>(val items: List<T>, val pageInfo: PageInfo)

fun fetchUsers(page: Int): Result<PaginatedData<User>> {
    return try {
        // Simulate API call
        val users = listOf(
            User(1, "John", "john@example.com"),
            User(2, "Jane", "jane@example.com")
        )
        Result.Success(
            data = PaginatedData(
                items = users,
                pageInfo = PageInfo(page = page, pageSize = 10, total = 2)
            )
        )
    } catch (e: Exception) {
        Result.Error(code = 500, message = "Failed to fetch user list", cause = e)
    }
}

fun handleResult(result: Result<PaginatedData<User>>) {
    when (result) {
        is Result.Success -> {
            val (data, message) = result
            val (items, pageInfo) = data
            println("$message, total ${pageInfo.total} records")
            items.forEach { (id, name, email) ->
                println("  - $name ($email)")
            }
        }
        is Result.Error -> {
            val (code, message, _) = result
            println("Error [$code]: $message")
        }
        Result.Loading -> println("Loading...")
    }
}

fun main() {
    val result = fetchUsers(1)
    handleResult(result)
}
```

## Best Practices

### Prefer val for Immutability

```kotlin
// Recommended: Immutable data class
data class ImmutableOrder(
    val id: String,
    val items: List<String>,  // Use immutable List
    val createdAt: Instant
)

// Not recommended: Mutable data class
data class MutableOrder(
    var id: String,
    var items: MutableList<String>,  // Mutable collection
    var createdAt: Instant
)
```

### Use List Instead of Array

```kotlin
// Recommended: Use List
data class Tags(val values: List<String>)

// Not recommended: Use Array (equals behavior is unexpected)
data class TagsWithArray(val values: Array<String>)

fun main() {
    val t1 = Tags(listOf("a", "b"))
    val t2 = Tags(listOf("a", "b"))
    println(t1 == t2)  // true - Correct

    val a1 = TagsWithArray(arrayOf("a", "b"))
    val a2 = TagsWithArray(arrayOf("a", "b"))
    println(a1 == a2)  // false - Array compares references!
}
```

### Provide Reasonable Default Values for Optional Properties

```kotlin
data class HttpRequest(
```

### Data Classes Focus on Data, Business Logic Externalized

```kotlin
// Data class only stores data
data class Invoice(
    val id: String,
    val items: List<InvoiceItem>,
    val discount: Double,
    val taxRate: Double
)

data class InvoiceItem(
    val productId: String,
    val quantity: Int,
    val unitPrice: Double
)

// Business logic goes in service classes or extension functions
class InvoiceCalculator {
    fun calculateSubtotal(invoice: Invoice): Double =
        invoice.items.sumOf { it.quantity * it.unitPrice }

    fun calculateTax(invoice: Invoice): Double =
        calculateSubtotal(invoice) * invoice.taxRate

    fun calculateTotal(invoice: Invoice): Double {
        val subtotal = calculateSubtotal(invoice)
        val afterDiscount = subtotal * (1 - invoice.discount)
        return afterDiscount * (1 + invoice.taxRate)
    }
}

// Or use extension functions
fun Invoice.subtotal(): Double = items.sumOf { it.quantity * it.unitPrice }
fun Invoice.total(): Double = subtotal() * (1 - discount) * (1 + taxRate)
```

## Common Pitfalls

### Array Type equals Pitfall

```kotlin
data class Container(val items: Array<String>)

fun main() {
    val c1 = Container(arrayOf("a", "b"))
    val c2 = Container(arrayOf("a", "b"))

    println(c1 == c2)  // false! Array uses reference comparison

    // If you must use Array, you need to manually override equals/hashCode
    data class SafeContainer(val items: Array<String>) {
        override fun equals(other: Any?): Boolean {
            if (this === other) return true
            if (other !is SafeContainer) return false
            return items.contentEquals(other.items)
        }

        override fun hashCode(): Int = items.contentHashCode()
    }

    // Better solution: Use List
    data class BetterContainer(val items: List<String>)
}
```

### Class Body Properties Don't Participate in copy()

```kotlin
data class Message(val id: Int, val content: String) {
    var readCount: Int = 0
    val createdAt: Long = System.currentTimeMillis()
}

fun main() {
    val original = Message(1, "Hello")
    original.readCount = 5

    val copied = original.copy(content = "Hi")

    println("Original readCount: ${original.readCount}")  // 5
    println("Copied readCount: ${copied.readCount}")      // 0 - Not copied!

    // Solution: Put properties that need to be copied in the primary constructor
    data class BetterMessage(
        val id: Int,
        val content: String,
        val readCount: Int = 0,
        val createdAt: Long = System.currentTimeMillis()
    )
}
```

### Inheritance Restrictions

```kotlin
// Data classes are final and cannot be inherited
data class BaseUser(val name: String, val age: Int)
// class ExtendedUser(name: String, age: Int, val role: String) : BaseUser(name, age) // Compilation error

// Solution 1: Use composition
data class ExtendedUser(val user: BaseUser, val role: String)

// Solution 2: Use interfaces
interface UserInfo {
    val name: String
    val age: Int
}

data class BasicUser(override val name: String, override val age: Int) : UserInfo
data class AdminUser(
    override val name: String,
    override val age: Int,
    val permissions: List<String>
) : UserInfo

// Solution 3: Use sealed classes
sealed class User {
    abstract val name: String
    abstract val age: Int

    data class Regular(override val name: String, override val age: Int) : User()
    data class Admin(override val name: String, override val age: Int, val level: Int) : User()
}
```

### hashCode and Mutable Properties

```kotlin
data class MutableKey(var value: String)

fun main() {
    val map = mutableMapOf<MutableKey, String>()
    val key = MutableKey("original")

    map[key] = "data"
    println(map[key])  // "data"

    key.value = "modified"  // Modified the key
    println(map[key])  // null! hashCode changed, can't find it anymore

    // Lesson: Data classes used as Map keys or Set elements must use val
}
```

### Destructuring Order Dependency

```kotlin
data class Person(val name: String, val age: Int)

// If parameter order is modified in the future
data class PersonV2(val age: Int, val name: String)  // Dangerous!

fun main() {
    val p = PersonV2(25, "John")
    val (name, age) = p  // Destructuring still by position, but meaning changed!
    println("$name years old $age")  // 25 years old John - Logic error

    // Best practice: Use property access instead of destructuring, or ensure API stability
}
```

### Deep Copy vs Shallow Copy

```kotlin
data class Team(val name: String, val members: MutableList<String>)

fun main() {
    val team1 = Team("Team A", mutableListOf("John", "Jane"))
    val team2 = team1.copy()  // Shallow copy

    team2.members.add("Bob")  // Modify team2's members

    println("team1: ${team1.members}")  // [John, Jane, Bob] - team1 was also modified!
    println("team2: ${team2.members}")  // [John, Jane, Bob]

    // Solution: Manual deep copy
    val team3 = team1.copy(members = team1.members.toMutableList())
    team3.members.add("Alice")

    println("team1: ${team1.members}")  // [John, Jane, Bob] - Unaffected
    println("team3: ${team3.members}")  // [John, Jane, Bob, Alice]

    // Better solution: Use immutable collections
    data class ImmutableTeam(val name: String, val members: List<String>)
}
```

## Performance Considerations

### Compile-time Generation vs Runtime Reflection

Data class methods are generated at compile time with no runtime reflection overhead:

```kotlin
data class Point(val x: Int, val y: Int)

// The bytecode after compilation is almost identical to a handwritten regular class
// No additional runtime overhead
```

### hashCode Calculation Optimization

When frequently using objects as Map keys, you can cache the hashCode:

```kotlin
// Regular data class calculates hashCode each time
data class FrequentKey(val a: String, val b: String, val c: String)

// Version with cached hashCode
class CachedHashKey(val a: String, val b: String, val c: String) {
    private val cachedHash: Int = computeHash()

    private fun computeHash(): Int {
        var result = a.hashCode()
        result = 31 * result + b.hashCode()
        result = 31 * result + c.hashCode()
        return result
    }

    override fun hashCode(): Int = cachedHash

    override fun equals(other: Any?): Boolean {
        if (this === other) return true
        if (other !is CachedHashKey) return false
        return a == other.a && b == other.b && c == other.c
    }
}
```

### Memory Impact of copy()

Each `copy()` creates a new object; be mindful in hot paths:

```kotlin
data class State(val count: Int, val items: List<String>)

// Not recommended: Frequent copy in loops
fun updateAllItems(state: State, transform: (String) -> String): State {
    var current = state
    for (i in state.items.indices) {
        current = current.copy(
            items = current.items.toMutableList().apply { set(i, transform(get(i))) }
        )
    }
    return current  // Creates n intermediate objects
}

// Recommended: Update all at once
fun updateAllItemsOptimized(state: State, transform: (String) -> String): State {
    return state.copy(items = state.items.map(transform))  // Only creates 1 new object
}
```

### Considerations for Large Data Classes

Data classes with many properties will generate larger equals/hashCode methods:

```kotlin
// With many properties, consider whether all need to participate in comparison
data class LargeEntity(
    val id: String,           // Unique identifier
    val name: String,
    val description: String,
    val metadata: Map<String, Any>,
    val tags: List<String>,
    // ... more properties
)

// If comparison by id only is needed, consider manual implementation
data class OptimizedEntity(
    val id: String,
    val name: String,
    val description: String
) {
    override fun equals(other: Any?): Boolean {
        if (this === other) return true
        if (other !is OptimizedEntity) return false
        return id == other.id  // Only compare id
    }

    override fun hashCode(): Int = id.hashCode()
}
```

```kotlin
sealed class OrderEvent {
    abstract val orderId: String
    abstract val timestamp: Instant

    data class Created(
        override val orderId: String,
        override val timestamp: Instant,
        val customerId: String,
        val items: List<OrderItem>
    ) : OrderEvent()

    data class ItemAdded(
        override val orderId: String,
        override val timestamp: Instant,
        val item: OrderItem
    ) : OrderEvent()

    data class Paid(
        override val orderId: String,
        override val timestamp: Instant,
        val amount: BigDecimal,
        val paymentMethod: String
    ) : OrderEvent()

    data class Shipped(
        override val orderId: String,
        override val timestamp: Instant,
        val trackingNumber: String,
        val carrier: String
    ) : OrderEvent()

    data class Cancelled(
        override val orderId: String,
        override val timestamp: Instant,
        val reason: String
    ) : OrderEvent()
}

// Event replay
fun rebuildOrder(events: List<OrderEvent>): Order? {
    return events.fold<OrderEvent, Order?>(null) { order, event ->
        when (event) {
            is OrderEvent.Created -> Order(
                id = event.orderId,
                customerId = event.customerId,
                items = event.items,
                status = OrderStatus.CREATED
            )
            is OrderEvent.ItemAdded -> order?.copy(
                items = order.items + event.item
            )
            is OrderEvent.Paid -> order?.copy(status = OrderStatus.PAID)
            is OrderEvent.Shipped -> order?.copy(status = OrderStatus.SHIPPED)
            is OrderEvent.Cancelled -> order?.copy(status = OrderStatus.CANCELLED)
        }
    }
}
```

## Interview Key Points

### Basic Questions

**Q1: What's the difference between data classes and regular classes?**

Data classes are declared with the `data` keyword, and the compiler automatically generates `equals()`, `hashCode()`, `toString()`, `componentN()`, and `copy()` methods. Regular classes require manual implementation of these methods. Data classes are mainly used for storing data, while regular classes can contain more complex behavioral logic.

**Q2: What are the restrictions for defining a data class?**

- The primary constructor must have at least one parameter
- All primary constructor parameters must be marked with `val` or `var`
- Data classes cannot be abstract, open, sealed, or inner
- Data classes can implement interfaces and extend sealed classes

**Q3: Is the copy() function a deep copy or shallow copy?**

`copy()` performs a shallow copy. It creates a new object, but internal reference type properties (such as collections, objects) still point to the original objects. If deep copy is needed, you must manually copy nested objects.

### Advanced Questions

**Q4: Why is val recommended over var for data classes?**

- Immutability makes code safer, avoiding accidental modifications
- Immutable objects are inherently thread-safe
- Easier to reason about program state
- Combined with `copy()`, you can elegantly create modified copies
- Using `var` can cause hashCode to change, affecting behavior in Sets/Maps

**Q5: What's the difference between properties defined in the class body and primary constructor properties?**

Properties in the primary constructor participate in the generation of `equals()`, `hashCode()`, `toString()`, `componentN()`, and `copy()`. Properties defined in the class body don't participate in these methods and are not copied during `copy()`.

**Q6: How to solve the equals issue when using Array in data classes?**

There are two solutions:
1. Use `List` instead of `Array` (recommended)
2. Manually override `equals()` and `hashCode()`, using `contentEquals()` and `contentHashCode()`

### Scenario Questions

**Q7: In Android development, what are common use cases for data classes?**

- UI State (State in ViewModel)
- API request/response DTOs
- Database entities (Room Entity)
- Data passed via Intent/Bundle
- RecyclerView list item data

**Q8: How would you design a data structure representing "loading/success/failure" three states?**

Use sealed class combined with data class:

```kotlin
sealed class LoadState<out T> {
    data object Loading : LoadState<Nothing>()
    data class Success<T>(val data: T) : LoadState<T>()
    data class Error(val exception: Throwable) : LoadState<Nothing>()
}
```

**Q9: Can data classes be inherited? How to achieve similar inheritance effects?**

Data classes are final and cannot be inherited. Similar effects can be achieved through:
1. Composition: Using the base class as a property of the data class
2. Interfaces: Having multiple data classes implement the same interface
3. Sealed classes: Data classes as subclasses of sealed classes
