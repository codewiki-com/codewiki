In the Rust ecosystem, `anyhow` and `thiserror` are two complementary error handling libraries, developed and maintained by David Tolnay. They address error handling needs in different scenarios: `thiserror` is used for defining structured custom error types, suitable for library development; `anyhow` provides convenient error handling, suitable for application development.

## Concept Explanation

### Why Do We Need These Two Libraries

The Rust standard library's `std::error::Error` trait provides the foundation for error handling, but manually implementing it requires a lot of boilerplate code:

```rust
use std::error::Error;
use std::fmt;

#[derive(Debug)]
struct MyError {
    message: String,
}

// Manual implementation requires writing a lot of code
impl fmt::Display for MyError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "{}", self.message)
    }
}

impl Error for MyError {}
```

`thiserror` automatically generates these implementations through derive macros, while `anyhow` provides a generic error type to simplify error propagation.

### thiserror: Designed for Library Authors

The core functionality of `thiserror` is to automatically implement the `std::error::Error` trait through the `#[derive(Error)]` macro. It's suitable for:

- Libraries that need to define explicit error types
- Scenarios where callers need to match and handle specific errors
- Public APIs that need to maintain backward compatibility

### anyhow: Designed for Application Developers

`anyhow` provides the `anyhow::Error` type, which can wrap any type that implements `std::error::Error`. It's suitable for:

- Top-level error handling in applications
- Rapid prototyping
- Scenarios where callers don't need to distinguish specific error types

## Core Principles

### thiserror's Macro Expansion Mechanism

`thiserror` uses procedural macros to generate code at compile time. Here's an example of macro expansion:

```rust
// Code you write
use thiserror::Error;

#[derive(Error, Debug)]
#[error("Data parsing failed: {message}")]
struct ParseError {
    message: String,
}

// Code automatically generated by thiserror (simplified)
impl std::fmt::Display for ParseError {
    fn fmt(&self, f: &mut std::fmt::Formatter) -> std::fmt::Result {
        write!(f, "Data parsing failed: {}", self.message)
    }
}

impl std::error::Error for ParseError {}
```

### Internal Structure of anyhow::Error

`anyhow::Error` is a smart pointer type that internally contains:

1. **Error object**: The original error that implements `std::error::Error`
2. **Error chain (backtrace)**: Optional stack trace information
3. **Context chain**: Additional information added via `.context()`

```rust
// Conceptual model of anyhow::Error
struct Error {
    inner: Box<dyn std::error::Error + Send + Sync + 'static>,
    backtrace: Option<Backtrace>,
    context: Vec<String>,
}
```

### From Trait and Error Conversion

Both libraries extensively use the `From` trait to implement automatic error conversion:

```rust
use thiserror::Error;
use std::io;

#[derive(Error, Debug)]
enum AppError {
    #[error("IO error")]
    Io(#[from] io::Error),  // Automatically generates From<io::Error> implementation
}

// From implementation generated by thiserror
impl From<io::Error> for AppError {
    fn from(source: io::Error) -> Self {
        AppError::Io(source)
    }
}
```

## Key Points

### thiserror Attributes Overview

| Attribute | Purpose | Example |
|-----------|---------|---------|
| `#[error("...")]` | Define Display output | `#[error("File not found: {path}")]` |
| `#[from]` | Automatically implement From trait | `Io(#[from] io::Error)` |
| `#[source]` | Mark error source | `#[source] inner: io::Error` |
| `#[backtrace]` | Capture backtrace | `backtrace: std::backtrace::Backtrace` |
| `transparent` | Transparent delegation | `#[error(transparent)]` |

### anyhow API Overview

| API | Purpose | Example |
|-----|---------|---------|
| `anyhow!()` | Create ad-hoc error | `anyhow!("An error occurred")` |
| `bail!()` | Early return with error | `bail!("Validation failed")` |
| `ensure!()` | Conditional check | `ensure!(x > 0, "Must be positive")` |
| `.context()` | Add context | `result.context("While processing config")?` |
| `.with_context()` | Lazy context loading | `.with_context(\|\| format!("Line {}", n))?` |
| `Error::downcast_ref()` | Downcast | `err.downcast_ref::<IoError>()` |

### Decision Tree for Selection

```
Do you need to define error types?
├── Yes: Are you developing a library?
│   ├── Yes → Use thiserror
│   └── No: Does the caller need to match specific errors?
│       ├── Yes → Use thiserror
│       └── No → Use anyhow
└── No: Only need to propagate and display errors
    └── Use anyhow
```

## Code Examples

### thiserror Basic Usage

```rust
use thiserror::Error;
use std::io;
use std::num::ParseIntError;

/// Application error type
#[derive(Error, Debug)]
pub enum AppError {
    /// IO operation failed
    #[error("IO error: {0}")]
    Io(#[from] io::Error),

    /// Integer parsing failed
    #[error("Parse error: {0}")]
    Parse(#[from] ParseIntError),

    /// Configuration validation failed
    #[error("Invalid configuration: {field} - {reason}")]
    Config { field: String, reason: String },

    /// Resource not found
    #[error("{resource_type} not found: {id}")]
    NotFound {
        resource_type: &'static str,
        id: String,
    },

    /// Insufficient permissions
    #[error("Permission denied: requires {required} permission")]
    PermissionDenied { required: String },
}

// Using custom errors
fn load_config(path: &str) -> Result<Config, AppError> {
    let content = std::fs::read_to_string(path)?; // io::Error automatically converted

    let port: u16 = content
        .lines()
        .find(|l| l.starts_with("port="))
        .ok_or_else(|| AppError::Config {
            field: "port".to_string(),
            reason: "Missing port configuration".to_string(),
        })?
        .trim_start_matches("port=")
        .parse()?; // ParseIntError automatically converted

    Ok(Config { port })
}

#[derive(Debug)]
struct Config {
    port: u16,
}
```

### thiserror Advanced Features

```rust
use thiserror::Error;
use std::backtrace::Backtrace;

/// Error type with source error and backtrace
#[derive(Error, Debug)]
pub enum DatabaseError {
    /// Connection failed, preserving original error
    #[error("Database connection failed")]
    Connection {
        #[source]
        source: std::io::Error,
        host: String,
        port: u16,
    },

    /// Query execution failed, with backtrace
    #[error("Query execution failed: {query}")]
    Query {
        query: String,
        #[backtrace]
        backtrace: Backtrace,
    },

    /// Transparently wrap other errors
    #[error(transparent)]
    Other(#[from] anyhow::Error),
}

/// Generic error type
#[derive(Error, Debug)]
#[error("Failed while processing {item}: {source}")]
pub struct ProcessError<T: std::fmt::Debug> {
    pub item: T,
    #[source]
    pub source: std::io::Error,
}

/// Enum variant formatting
#[derive(Error, Debug)]
pub enum ValidationError {
    #[error("Field `{0}` cannot be empty")]
    EmptyField(String),

    #[error("Field `{field}` value `{value}` is out of range [{min}, {max}]")]
    OutOfRange {
        field: String,
        value: i64,
        min: i64,
        max: i64,
    },

    #[error("Format mismatch: expected {expected}, got {actual}")]
    FormatMismatch { expected: String, actual: String },
}
```

### anyhow Basic Usage

```rust
use anyhow::{anyhow, bail, Context, Result};
use std::fs::File;
use std::io::Read;

/// Using anyhow::Result<T> to simplify return type
fn read_config_file(path: &str) -> Result<String> {
    let mut file = File::open(path)
        .context(format!("Cannot open config file: {}", path))?;

    let mut content = String::new();
    file.read_to_string(&mut content)
        .context("Failed to read config content")?;

    if content.is_empty() {
        bail!("Config file is empty");
    }

    Ok(content)
}

/// Parse configuration and validate
fn parse_server_config(content: &str) -> Result<ServerConfig> {
    let port = content
        .lines()
        .find(|l| l.starts_with("port="))
        .ok_or_else(|| anyhow!("Missing port configuration"))?
        .trim_start_matches("port=")
        .parse::<u16>()
        .context("port must be a valid port number")?;

    let host = content
        .lines()
        .find(|l| l.starts_with("host="))
        .map(|l| l.trim_start_matches("host=").to_string())
        .unwrap_or_else(|| "127.0.0.1".to_string());

    Ok(ServerConfig { host, port })
}

#[derive(Debug)]
struct ServerConfig {
    host: String,
    port: u16,
}

/// Combining multiple fallible operations
fn initialize_server(config_path: &str) -> Result<()> {
    let content = read_config_file(config_path)
        .context("Failed during configuration loading phase")?;

    let config = parse_server_config(&content)
        .context("Failed during configuration parsing phase")?;

    println!("Server config: {}:{}", config.host, config.port);
    Ok(())
}

fn main() {
    if let Err(e) = initialize_server("config.toml") {
        // Print complete error chain
        eprintln!("Error: {:#}", e);

        // Or print level by level
        eprintln!("\nDetailed error chain:");
        for (i, cause) in e.chain().enumerate() {
            eprintln!("  {}: {}", i, cause);
        }
    }
}
```

### anyhow Advanced Usage

```rust
use anyhow::{anyhow, ensure, Context, Result};
use std::collections::HashMap;

/// ensure! macro for conditional validation
fn validate_user(data: &HashMap<String, String>) -> Result<User> {
    ensure!(data.contains_key("name"), "Missing required field: name");
    ensure!(data.contains_key("email"), "Missing required field: email");
    ensure!(data.contains_key("age"), "Missing required field: age");

    let name = data["name"].clone();
    ensure!(!name.is_empty(), "name cannot be empty");
    ensure!(name.len() <= 100, "name length cannot exceed 100 characters");

    let email = data["email"].clone();
    ensure!(email.contains('@'), "Invalid email format");

    let age: u8 = data["age"]
        .parse()
        .context("age must be a valid number")?;
    ensure!(age >= 18, "User must be at least 18 years old");
    ensure!(age <= 150, "age value is unreasonable");

    Ok(User { name, email, age })
}

#[derive(Debug)]
struct User {
    name: String,
    email: String,
    age: u8,
}

/// with_context for lazy context loading (performance optimization)
fn process_items(items: &[String]) -> Result<Vec<i32>> {
    items
        .iter()
        .enumerate()
        .map(|(i, item)| {
            item.parse::<i32>()
                .with_context(|| format!("Failed to parse item {}: '{}'", i + 1, item))
        })
        .collect()
}

/// Error fallback handling
fn get_cached_value(key: &str) -> Result<String> {
    // Primary path
    match fetch_from_primary(key) {
        Ok(value) => return Ok(value),
        Err(e) => {
            eprintln!("Primary path failed, trying backup: {}", e);
        }
    }

    // Backup path
    fetch_from_backup(key)
        .context("Both primary and backup paths failed")
}

fn fetch_from_primary(_key: &str) -> Result<String> {
    Err(anyhow!("Primary service unavailable"))
}

fn fetch_from_backup(_key: &str) -> Result<String> {
    Ok("backup value".to_string())
}

/// Downcasting to get original error
fn handle_error_with_downcast(err: &anyhow::Error) {
    // Check if it's a specific error type
    if let Some(io_err) = err.downcast_ref::<std::io::Error>() {
        match io_err.kind() {
            std::io::ErrorKind::NotFound => {
                println!("File not found, will create default config");
            }
            std::io::ErrorKind::PermissionDenied => {
                println!("Permission denied, please run as administrator");
            }
            _ => {
                println!("Other IO error: {}", io_err);
            }
        }
    } else {
        println!("Unknown error type: {}", err);
    }
}
```

### Using Both Together

```rust
use anyhow::{Context, Result};
use thiserror::Error;
use std::io;

/// Library level uses thiserror to define explicit error types
#[derive(Error, Debug)]
pub enum StorageError {
    #[error("Storage connection failed: {0}")]
    Connection(#[from] io::Error),

    #[error("Data serialization failed: {0}")]
    Serialization(#[from] serde_json::Error),

    #[error("Key '{key}' does not exist")]
    KeyNotFound { key: String },

    #[error("Storage capacity exceeded")]
    CapacityExceeded,
}

/// Library's public API
pub struct Storage {
    // ...
}

impl Storage {
    pub fn get(&self, key: &str) -> Result<String, StorageError> {
        // Returns specific error type, caller can match
        Err(StorageError::KeyNotFound {
            key: key.to_string(),
        })
    }

    pub fn set(&self, _key: &str, _value: &str) -> Result<(), StorageError> {
        Ok(())
    }
}

/// Application level uses anyhow to handle all errors
fn application_logic() -> Result<()> {
    let storage = Storage {};

    // StorageError automatically converts to anyhow::Error
    let value = storage
        .get("config")
        .context("Failed to get configuration")?;

    println!("Config value: {}", value);
    Ok(())
}

/// Can downcast back to original error when needed
fn handle_storage_error() -> Result<()> {
    let storage = Storage {};

    match storage.get("user_id") {
        Ok(v) => println!("User ID: {}", v),
        Err(StorageError::KeyNotFound { key }) => {
            println!("Key {} does not exist, using default value", key);
        }
        Err(e) => {
            // Propagate other errors upward
            return Err(e.into());
        }
    }

    Ok(())
}
```

## Best Practices

### Layered Design for Libraries and Applications

```rust
// ===== Library Layer (using thiserror) =====
// lib.rs
use thiserror::Error;

/// Public error type, allows caller pattern matching
#[derive(Error, Debug)]
#[non_exhaustive]  // Preserve backward compatibility
pub enum LibError {
    #[error("Invalid input: {0}")]
    InvalidInput(String),

    #[error("Operation timeout")]
    Timeout,

    #[error("Internal error")]
    Internal(#[source] Box<dyn std::error::Error + Send + Sync>),
}

pub fn library_function() -> Result<String, LibError> {
    // Library function returns specific error type
    Ok("result".to_string())
}

// ===== Application Layer (using anyhow) =====
// main.rs
use anyhow::{Context, Result};

fn main() -> Result<()> {
    let result = library_function()
        .context("Failed to call library function")?;

    println!("{}", result);
    Ok(())
}
```

### Error Message Design Principles

```rust
use thiserror::Error;

#[derive(Error, Debug)]
pub enum ConfigError {
    // Good: Explains what happened, where, and possible cause
    #[error("Failed to parse line {line} of config file '{path}': {reason}")]
    ParseError {
        path: String,
        line: usize,
        reason: String,
    },

    // Good: Provides sufficient context
    #[error("Environment variable '{name}' not set (required for {purpose})")]
    MissingEnvVar {
        name: String,
        purpose: String,
    },

    // Avoid: Too vague
    // #[error("Configuration error")]
    // Generic,

    // Avoid: Exposes internal implementation details
    // #[error("HashMap index out of bounds")]
    // InternalError,
}
```

### Context Addition Strategy

```rust
use anyhow::{Context, Result};

fn process_user_data(user_id: u32) -> Result<()> {
    // Strategy 1: Add context at boundaries
    let user = fetch_user(user_id)
        .with_context(|| format!("Failed to fetch data for user {}", user_id))?;

    // Strategy 2: Add iteration info for loop operations
    for (i, item) in user.items.iter().enumerate() {
        process_item(item)
            .with_context(|| format!("Processing item {} for user {}", i + 1, user_id))?;
    }

    // Strategy 3: Summarize at high-level operations
    save_results(&user)
        .context("Failed to save user processing results")?;

    Ok(())
}

fn fetch_user(_id: u32) -> Result<User> {
    Ok(User { items: vec![] })
}

fn process_item(_item: &str) -> Result<()> {
    Ok(())
}

fn save_results(_user: &User) -> Result<()> {
    Ok(())
}

struct User {
    items: Vec<String>,
}
```

```rust
use anyhow::{Context, Result};
use tracing::{error, info, instrument, warn};

fn process_request(request_id: &str, config: &Config) -> Result<Response> {

}

    Ok("cached".to_string())
```

## Common Pitfalls

### Using anyhow in Libraries

```rust
// Wrong: Library using anyhow prevents caller from matching specific errors
// lib.rs
pub fn library_fn() -> anyhow::Result<()> {
    // Caller cannot distinguish different error cases
    Err(anyhow::anyhow!("Failed"))
}

// Correct: Library uses thiserror to define explicit error types
use thiserror::Error;

#[derive(Error, Debug)]
pub enum LibError {
    #[error("Type A error")]
    TypeA,
    #[error("Type B error")]
    TypeB,
}

pub fn library_fn() -> Result<(), LibError> {
    Err(LibError::TypeA)
}
```

### Losing the Error Chain

```rust
use anyhow::{anyhow, Context, Result};

// Wrong: Creating new error loses original error
fn bad_error_handling() -> Result<()> {
    let result = std::fs::read_to_string("file.txt");
    match result {
        Ok(s) => Ok(()),
        // Lost the original io::Error
        Err(_) => Err(anyhow!("Failed to read file")),
    }
}

// Correct: Preserve error chain
fn good_error_handling() -> Result<()> {
    std::fs::read_to_string("file.txt")
        .context("Failed to read file")?;
    Ok(())
}
```

### Overusing context

```rust
use anyhow::{Context, Result};

// Bad: Adding context at every step leads to redundancy
fn over_contexted() -> Result<i32> {
    let s = "42";
    let trimmed = s.trim();  // Won't fail, no context needed
    let parsed = trimmed
        .parse::<i32>()
        .context("Parse failed")?;  // Context makes sense here
    let result = parsed
        .checked_add(1)
        .ok_or_else(|| anyhow::anyhow!("Overflow"))
        .context("Addition failed")?;  // Redundant: already has clear error message

    Ok(result)
}

// Good: Add context where meaningful
fn properly_contexted(input: &str) -> Result<i32> {
    input
        .trim()
        .parse::<i32>()
        .context("Input must be a valid integer")?
        .checked_add(1)
        .ok_or_else(|| anyhow::anyhow!("Calculation result overflowed"))
}
```

### Ignoring the Difference Between #[from] and #[source]

```rust
use thiserror::Error;
use std::io;

#[derive(Error, Debug)]
enum MyError {
    // #[from]: Implements From trait and marks as source
    // Suitable when error variant contains only a single error
    #[error("IO error")]
    Io(#[from] io::Error),

    // #[source]: Only marks as error source, doesn't implement From
    // Suitable when additional fields are needed
    #[error("Error occurred while processing file {path}")]
    FileProcess {
        path: String,
        #[source]
        source: io::Error,
    },
}

// Using #[from] variant
fn use_from() -> Result<(), MyError> {
    std::fs::read_to_string("test.txt")?;  // Automatic conversion
    Ok(())
}

// Using #[source] variant
fn use_source(path: &str) -> Result<(), MyError> {
    std::fs::read_to_string(path)
        .map_err(|e| MyError::FileProcess {
            path: path.to_string(),
            source: e,
        })?;
    Ok(())
}
```

### Send Issues in Async Code

```rust
use anyhow::Result;
use std::rc::Rc;

// Wrong: Rc is not Send, cannot cross await point
async fn bad_async() -> Result<()> {
    let data = Rc::new(vec![1, 2, 3]);
    // Compile error: future is not Send
    tokio::time::sleep(std::time::Duration::from_secs(1)).await;
    println!("{:?}", data);
    Ok(())
}

// Correct: Use Arc instead of Rc
use std::sync::Arc;

async fn good_async() -> Result<()> {
    let data = Arc::new(vec![1, 2, 3]);
    tokio::time::sleep(std::time::Duration::from_secs(1)).await;
    println!("{:?}", data);
    Ok(())
}
```

## Performance Considerations

### Cost of the Error Path

```rust
use anyhow::{anyhow, Context, Result};
use std::hint::black_box;

// anyhow::Error allocates on the heap, has some overhead
fn error_allocation_cost() -> Result<()> {
    // Each anyhow::Error creation performs heap allocation
    Err(anyhow!("Error message"))
}

// context() allocates new wrapper on each call
fn context_cost(path: &str) -> Result<String> {
    std::fs::read_to_string(path)
        .context("Read failed")  // Allocates on error
        .context("Process config")  // Allocates again on error
        .context("Initialize")?;  // Allocates again on error
    Ok(String::new())
}

// Optimization: Use with_context for lazy loading
fn lazy_context(path: &str) -> Result<String> {
    std::fs::read_to_string(path)
        // Closure only executes when error occurs
        .with_context(|| format!("Failed to read config file {}", path))?;
    Ok(String::new())
}
```

### thiserror vs anyhow Memory Footprint

```rust
use std::mem::size_of;
use thiserror::Error;

#[derive(Error, Debug)]
enum SmallError {
    #[error("Error A")]
    A,
    #[error("Error B")]
    B,
}

fn compare_sizes() {
    // thiserror enum: size equals largest variant
    println!("SmallError: {} bytes", size_of::<SmallError>());

    // anyhow::Error: fixed 8 bytes (one pointer)
    println!("anyhow::Error: {} bytes", size_of::<anyhow::Error>());

    // Result<(), SmallError>: usually 1-2 bytes
    println!("Result<(), SmallError>: {} bytes",
             size_of::<Result<(), SmallError>>());

    // Result<(), anyhow::Error>: 8 bytes
    println!("Result<(), anyhow::Error>: {} bytes",
             size_of::<anyhow::Result<()>>());
}
```

### Performance Impact of Backtrace

```rust
// Enable backtrace in Cargo.toml
// [dependencies]
// anyhow = { version = "1.0", features = ["backtrace"] }

use anyhow::Result;

// With RUST_BACKTRACE=1, every error captures backtrace
// This has significant performance overhead

fn with_backtrace() -> Result<()> {
    // When backtrace is enabled, error creation cost is higher
    Err(anyhow::anyhow!("Error with backtrace"))
}

// Production recommendation:
// 1. Enable RUST_BACKTRACE=1 during development
// 2. Don't set this variable in production
// 3. Or explicitly disable with RUST_BACKTRACE=0
```

### Hot Path Optimization

```rust
use anyhow::{bail, Result};

// Avoid frequent error object creation on hot paths
fn hot_path(items: &[i32]) -> Result<i32> {
    let mut sum = 0i32;
    for &item in items {
        // Bad: May create error object on each iteration
        // sum = sum.checked_add(item)
        //     .ok_or_else(|| anyhow!("Overflow"))?;

        // Good: Use lighter-weight check
        if let Some(new_sum) = sum.checked_add(item) {
            sum = new_sum;
        } else {
            bail!("Overflow occurred while calculating sum");
        }
    }
    Ok(sum)
}

// For extremely high performance requirements, consider custom error types
#[derive(Debug)]
struct OverflowError;

fn hot_path_custom(items: &[i32]) -> Result<i32, OverflowError> {
    let mut sum = 0i32;
    for &item in items {
        sum = sum.checked_add(item).ok_or(OverflowError)?;
    }
    Ok(sum)
}
```

## Real-World Scenarios

### Scenario 1: Web Service Error Handling

```rust
use anyhow::{Context, Result};
use axum::{
    http::StatusCode,
    response::{IntoResponse, Response},
    Json,
};
use serde::Serialize;
use thiserror::Error;

/// API error type (for external responses)
#[derive(Error, Debug)]
pub enum ApiError {
    #[error("Resource not found: {0}")]
    NotFound(String),

    #[error("Invalid request parameters: {0}")]
    BadRequest(String),

    #[error("Unauthorized access")]
    Unauthorized,

    #[error("Internal server error")]
    Internal(#[from] anyhow::Error),
}

/// API error response
#[derive(Serialize)]
struct ErrorResponse {
    code: u16,
    message: String,
}

impl IntoResponse for ApiError {
    fn into_response(self) -> Response {
        let (status, message) = match &self {
            ApiError::NotFound(msg) => (StatusCode::NOT_FOUND, msg.clone()),
            ApiError::BadRequest(msg) => (StatusCode::BAD_REQUEST, msg.clone()),
            ApiError::Unauthorized => (StatusCode::UNAUTHORIZED, "Unauthorized".to_string()),
            ApiError::Internal(e) => {
                // Log internal error details
                tracing::error!("Internal error: {:?}", e);
                (StatusCode::INTERNAL_SERVER_ERROR, "Internal server error".to_string())
            }
        };

        let body = Json(ErrorResponse {
            code: status.as_u16(),
            message,
        });

        (status, body).into_response()
    }
}

/// Handler function
async fn get_user(user_id: u32) -> Result<Json<User>, ApiError> {
    let user = find_user_by_id(user_id)
        .await
        .context("Failed to query user database")?
        .ok_or_else(|| ApiError::NotFound(format!("User {} does not exist", user_id)))?;

    Ok(Json(user))
}

async fn find_user_by_id(_id: u32) -> Result<Option<User>> {
    Ok(Some(User { id: 1, name: "Alice".to_string() }))
}

#[derive(Serialize)]
struct User {
    id: u32,
    name: String,
}
```

### Scenario 2: CLI Tool Error Handling

```rust
use anyhow::{bail, Context, Result};
use clap::Parser;
use std::path::PathBuf;

#[derive(Parser)]
struct Cli {
    /// Config file path
    #[arg(short, long, default_value = "config.toml")]
    config: PathBuf,

    /// Output directory
    #[arg(short, long)]
    output: PathBuf,

    /// Verbose output
    #[arg(short, long)]
    verbose: bool,
}

fn main() {
    let cli = Cli::parse();

    if let Err(e) = run(cli) {
        // Decide output format based on verbose flag
        if std::env::var("RUST_BACKTRACE").is_ok() {
            eprintln!("Error: {:?}", e);
        } else {
            eprintln!("Error: {:#}", e);
            eprintln!("\nHint: Set RUST_BACKTRACE=1 for detailed information");
        }
        std::process::exit(1);
    }
}

fn run(cli: Cli) -> Result<()> {
    // Verify config file exists
    if !cli.config.exists() {
        bail!(
            "Config file does not exist: {}\n\
             Please create a config file or use --config to specify path",
            cli.config.display()
        );
    }

    // Read config
    let config_content = std::fs::read_to_string(&cli.config)
        .with_context(|| format!("Cannot read config file: {}", cli.config.display()))?;

    // Parse config
    let config: Config = toml::from_str(&config_content)
        .context("Config file format error")?;

    // Verify output directory
    if !cli.output.exists() {
        std::fs::create_dir_all(&cli.output)
            .with_context(|| format!("Cannot create output directory: {}", cli.output.display()))?;
    }

    // Execute main logic
    process(&config, &cli.output)
        .context("Error occurred during processing")?;

    println!("Processing complete! Output directory: {}", cli.output.display());
    Ok(())
}

#[derive(serde::Deserialize)]
struct Config {
    name: String,
}

fn process(_config: &Config, _output: &PathBuf) -> Result<()> {
    Ok(())
}
```

### Scenario 3: Layered Error Design for Libraries

```rust
use thiserror::Error;
use std::io;

// ===== Low level: Storage layer errors =====
#[derive(Error, Debug)]
pub enum StorageError {
    #[error("Connection failed: {0}")]
    Connection(#[source] io::Error),

    #[error("Read failed: key={key}")]
    Read { key: String, #[source] source: io::Error },

    #[error("Write failed: key={key}")]
    Write { key: String, #[source] source: io::Error },

    #[error("Data corruption: {0}")]
    Corruption(String),
}

// ===== Middle level: Business logic layer errors =====
#[derive(Error, Debug)]
pub enum ServiceError {
    #[error("Storage error")]
    Storage(#[from] StorageError),

    #[error("User {user_id} does not exist")]
    UserNotFound { user_id: u64 },

    #[error("Permission denied: user {user_id} cannot access resource {resource}")]
    PermissionDenied { user_id: u64, resource: String },

    #[error("Validation failed: {0}")]
    Validation(String),
}

// ===== Top level: API layer errors =====
#[derive(Error, Debug)]
pub enum ApiError {
    #[error("Service error")]
    Service(#[from] ServiceError),

    #[error("Bad request format: {0}")]
    BadRequest(String),

    #[error("Authentication failed")]
    AuthenticationFailed,

    #[error("Rate limit exceeded")]
    RateLimited,
}

// Business logic layer
mod service {
    use super::*;

    pub fn get_user(user_id: u64) -> Result<User, ServiceError> {
        // Call storage layer
        let data = storage::read_user(user_id)?;

        // Validate data
        if data.is_empty() {
            return Err(ServiceError::UserNotFound { user_id });
        }

        Ok(User { id: user_id, data })
    }

    pub struct User {
        pub id: u64,
        pub data: String,
    }
}

// Storage layer
mod storage {
    use super::*;

    pub fn read_user(_user_id: u64) -> Result<String, StorageError> {
        Ok("user_data".to_string())
    }
}
```

## Interview Key Points

### Basic Questions

**Q1: What is the core difference between thiserror and anyhow? When should you use which?**

A: `thiserror` is used to define specific error types, automatically implementing the `Error` trait through derive macros. It's suitable for library development, allowing callers to match and handle specific errors. `anyhow` provides a generic error type `anyhow::Error` that can wrap any error and add context. It's suitable for application development.

Selection principles:
- Developing a library -> thiserror
- Developing an application -> anyhow
- Callers need to distinguish error types -> thiserror
- Only care about error propagation and display -> anyhow

**Q2: What's the difference between `#[from]` and `#[source]`?**

A: `#[from]` automatically implements the `From` trait and marks as error source. It's suitable when an error variant contains only a single error type, supporting automatic conversion with the `?` operator. `#[source]` only marks the field as error source without implementing `From`. It's suitable when additional fields are needed, requiring manual error construction.

**Q3: What's the difference between anyhow's `context()` and `with_context()`?**

A: `context()` immediately evaluates the context string, while `with_context()` accepts a closure for lazy loading, only computing when an error occurs. For complex context information requiring formatting, `with_context()` has better performance.

### Advanced Questions

**Q4: How do you downcast to get the original error in anyhow?**

```rust
use anyhow::Result;

fn handle_error(err: &anyhow::Error) {
    if let Some(io_err) = err.downcast_ref::<std::io::Error>() {
        // Handle IO error
    }
}
```

**Q5: How do you design an error type that supports both specific error matching and convenient propagation?**

A: Use thiserror to define specific errors, and implement `From<SpecificError> for anyhow::Error` (this is automatic), or add an `#[error(transparent)] Other(#[from] anyhow::Error)` variant to the error enum.

**Q6: What is the memory layout of anyhow::Error?**

A: `anyhow::Error` is a single pointer size (8 bytes on 64-bit), pointing to a heap-allocated error object. Internally it contains the original error, optional backtrace, and context chain. This makes `Result<T, anyhow::Error>` a fixed size, unaffected by the error type size.

### Practical Questions

**Q7: How do you gracefully handle errors in a web service?**

A: Define API layer error types, implement `IntoResponse` (Axum) or similar trait, converting internal errors to HTTP responses. For 500 errors, log detailed information but don't expose to users. For 4xx errors, provide useful error messages.

**Q8: How do you test error handling code?**

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_error_conversion() {
        let io_err = std::io::Error::new(std::io::ErrorKind::NotFound, "test");
        let my_err: MyError = io_err.into();
        assert!(matches!(my_err, MyError::Io(_)));
    }

    #[test]
    fn test_error_message() {
        let err = MyError::NotFound { item: "user".to_string() };
        assert_eq!(err.to_string(), "Not found: user");
    }

    #[test]
    fn test_error_chain() {
        let result: anyhow::Result<()> = Err(anyhow!("inner"))
            .context("outer");
        let err = result.unwrap_err();
        assert_eq!(err.chain().count(), 2);
    }
}
```
