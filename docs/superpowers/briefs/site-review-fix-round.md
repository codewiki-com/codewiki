# Fix round for the whole-site review — rulings for the implementer

Source: `docs/superpowers/ledgers/2026-09-04-site-review.md` (read it fully first). Branch `fix-site-review` from `main` (after `fix-ui-real-content` merged). Content fixes (interview coverage, TryToBreak, SQL seed, glossary term, banned phrase) run in parallel on other branches — do not touch `src/content/interview/**`, `src/content/glossary/**` or topic prose except for the deletions and reference sweeps named in I1.

## Rulings

**C1 — split the practice catalogue by track.** New static routes `/practice/{track}/` and `/zh/practice/{track}/` render that track's cards (≤ ~200) with the existing filter island (type, difficulty, sort, query-string state minus `track`). `/practice/` becomes a hub: the today strip and the flashcards/checkpoint strip as now, then a track grid (glyph, name, counts per item type, link to the track's practice page) — under 300 DOM elements, no cards. Every internal link that used `?track=` points at the new routes; the hub island still honours a legacy `?track=` by client-redirecting. On the track pages add `content-visibility: auto` + `contain-intrinsic-size` to cards and stop re-appending all anchors in `orderCards()` when the sort is unchanged. Add `/practice/javascript/` to `lighthouserc.json`; performance ≥ 0.95 on `/practice/` and `/practice/javascript/`. Sitemap includes the new routes; OG cards exist for them (extend `ogEntries`). Rewrite `practice-hub.spec.ts` for the new structure and wait for `data-ready` before asserting.

**I1 — duplicates.** Delete `python/scope` (→ `/python/scope-namespaces/`), `python/fastapi` (→ `/backend/fastapi/`), `python/django` (→ `/backend/django/`): both locales, their quiz banks `src/content/quizzes/python/{scope,fastapi,django}.yaml`, any glossary proposals. Sweep every reference to the deleted ids (`related`, `prerequisites`, paths, cheatsheets, interview `topics:` — retag to the survivor and drop exact duplicates, `content/new-topics.yaml`, `content/tiers.yaml`, `reports/polish/state.json` entries) to the survivors. Redirects in `public/_redirects` (301, six lines) and in `astro.config.mjs` `redirects` (so the preview works on any host); a unit test asserts the two lists agree and `scripts/check-dist-links.mjs` validates that `_redirects` targets exist in `dist`. Leave `go/reflect` / `go/reflection` (distinct titles since the taxonomy pass).

**I2 — cheatsheet snippets wrap.** `.snip` gets `white-space: pre-wrap; overflow-wrap: anywhere`; no scrollable regions remain; the 2-column print layout still fits; `a11y.spec.ts` green on `/cheatsheets/python/` in both palettes.

**I3 — rules never cut a sentence.** In `src/lib/rules.ts`, `why` comes only from a genuine second sentence; raise the clamp to 240 characters and, beyond that, keep the whole sentence rather than splitting it. Unit tests with the three examples quoted in the review; a test over all generated rules asserts zero entries ending in `…` followed by a `Why:` fragment.

**I4 — e2e gate green.** Re-baseline fixtures against the merged content, deriving counts and titles from the collections or the built HTML rather than literals where practical; `localization.spec.ts` allows technical identifiers (a token with no spaces that contains a digit, a dot, `+`, `#`, or an inner capital, or that is listed in a new `tests/e2e/fixtures/identifiers.ts`); disambiguate the five "Closures" locators by track URL. `pnpm test:e2e` must be fully green at the end.

**I5 — no empty promise.** Hide the per-topic "Interview bank" link (MetaPanel/ActionRow) when the track bank has no item tagged to that topic. The content side is being filled in parallel.

**Minors.** M1 `lighthouserc.json`: `numberOfRuns: 3`, `aggregationMethod: "median"`. M2 reserve the flashcard stage height before hydration (CLS < 0.05 on `/practice/flashcards/`). M3 `aria-label` "Filter by {track}" (i18n) on filter chips. M4 resolve `related`/`prerequisites` against the collection once and log one summary line instead of per-reference warnings (build warnings from this source → 0). M5 `PrevNext.astro`: planned title (from `content/tiers.yaml` when it carries titles, else the de-slugged text) plus the same `track.soon` tag TrackHub uses. M7 `overflow-x: clip` on the practice wrapper. M10 on `/tracks/`, tracks with fewer than 8 published topics carry a `preview` tag (i18n `track.preview`: "preview" / "预览"). M6, M8, M9, M11 are content and run elsewhere.
