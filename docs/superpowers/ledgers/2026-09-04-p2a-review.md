## Findings

### Critical

#### C1. Standalone kata answers are shipped in indexable HTML

- **Location:** `src/components/KataShell.astro:106`, `src/pages-shared/Kata.astro:205`, `tests/e2e/practice.spec.ts:13`
- **What is wrong:** `KataShell` renders the correct option/fill answer, issue notes, and explanation into `<template data-answer>`. `Kata.astro` also serializes the complete answer-bearing `item` into each Astro island's `props`. The built predict and review HTML contains the explanation, `correct: true`, review `right`, checklist, and issues before any attempt. The e2e test only checks `document.body.innerText` and explicitly asserts that the answer is present in the template, so it tests visual hiding rather than absence from indexable source.
- **Concrete failure scenario:** A crawler or a visitor using View Source can extract the correct answer and explanation from `/practice/predict/python/closures/predict-loop-binding/` without attempting the kata.
- **Smallest fix:** Pass an answer-free item DTO to the server shell/island, remove `template[data-answer]`, and load the answer-bearing data only after the visitor submits/reveals/compares. Change the e2e assertion to inspect the response HTML and fail on answer text or correctness flags. No built HTML currently links or prefetches `.answers.json`; the only source reference is the flashcard reviewer's on-demand fetch at `src/islands/Flashcards.tsx:339`, so that half of the boundary is intact.

### Important

#### I1. P2 Chinese routes render extensive English UI

- **Location:** `src/i18n/zh.ts:160`, `src/i18n/zh.ts:227`, `src/i18n/zh.ts:267`, `src/i18n/zh.ts:368`, `src/i18n/zh.ts:412`, `src/i18n/zh.ts:445`, `src/i18n/zh.ts:478`, `src/pages-shared/Path.astro:48`, `src/lib/cards.ts:146`, `src/islands/Flashcards.tsx:468`
- **What is wrong:** Almost every P2 value in the Chinese dictionary is still its English placeholder. Planned path-node labels and flashcard cues/tags also bypass `t()` and are hard-coded in English. Although the plan schedules placeholder translation for Task 17, this review's explicit P2a acceptance condition says that P2 `/zh/` pages must not expose English UI.
- **Concrete failure scenario:** Browser checks of `/zh/practice/`, `/zh/paths/python-from-zero/`, `/zh/practice/flashcards/`, and `/zh/settings/` showed visible strings including “Practice”, “Learning paths”, “Continue”, “Review”, “Interview reveal mode”, and full English paragraphs. `tests/e2e/localization.spec.ts:41` misses this because it covers only two older routes and scans only `.lbl, .tag`.
- **Smallest fix:** Translate all P2 keys now, localize planned-node labels and card cues/tags through the dictionaries, and extend the localization test to every P2 Chinese page shape and visible body/control text.

#### I2. The public “answer-free” quiz endpoint exposes review solution material

- **Location:** `src/lib/practice.ts:82`, `src/schemas/quiz.ts:44`, `tests/unit/practice.test.ts:143`
- **What is wrong:** `stripAnswers()` removes `issues` and `explanation` from review items but leaves the review-only `right` and `checklist` fields. The unit fixture does not populate either field, so its recursive-string assertion cannot catch the omission.
- **Concrete failure scenario:** `/api/quizzes/python/closures.json` currently returns “The function handles an empty YAML document…” plus the three-item expert checklist for `review-config-loader`, before the user performs the review.
- **Smallest fix:** Delete `right` and `checklist` for review items in `stripAnswers()` and add non-empty values for both to the stripping test fixture.

#### I3. Structurally corrupt stores crash checkpoint completion

- **Location:** `src/lib/prefs.ts:176`, `src/islands/Checkpoint.tsx:235`, `src/lib/score.ts:18`, `src/lib/score.ts:46`
- **What is wrong:** `readStore()` validates only that non-preference data is an object; it returns `{ quizzes: null, topics: null, paths: null }` as `Progress` and `{ cards: null }` as `Flashcards`. Checkpoint then passes those values to helpers that dereference `progress.quizzes[id]` or call `deck.cards.map()`.
- **Concrete failure scenario:** With `cw:v1:progress` set to `{"quizzes":null,"topics":null,"paths":null}`, answering the final checkpoint item produced the browser error `Cannot read properties of null (reading 'python/closures')`; the result screen never appeared. A corrupt flashcard object similarly fails “Add misses”.
- **Smallest fix:** Add per-key sanitizers in `prefs.ts` for progress, flashcards, and recents (including nested collections), return the provided defaults for invalid shapes, and cover checkpoint completion/add-misses with malformed stored objects.

#### I4. The path map has a serious nested-interactive accessibility violation

- **Location:** `src/components/PathMap.astro:32`, `src/components/PathMap.astro:101`, `tests/e2e/a11y.spec.ts:11`
- **What is wrong:** The complete `<svg>` is assigned `role="img"` while authored topic nodes inside it are focusable `<a>` elements. A manual axe sweep of every P2 page shape in both themes reports `nested-interactive` (serious, WCAG 4.1.2) on `.path-svg` in light and dark modes. The committed axe matrix only contains `/`, `/python/`, and `/python/closures/`, so it cannot catch this.
- **Concrete failure scenario:** A screen-reader user can focus the Closures link inside an element exposed as one image; axe reports that this structure may omit the nested control announcement or cause focus problems.
- **Smallest fix:** Do not expose the container as an image when it contains links: remove `role="img"`/use a non-interactive grouping semantic with an accessible title, keep decorative SVG parts hidden, and preserve accessible names on each link. Add all P2 page shapes to the two-theme axe matrix.

#### I5. Checkpoint transitions drop keyboard focus to the document body

- **Location:** `src/islands/Checkpoint.tsx:209`, `src/islands/Checkpoint.tsx:230`, `src/islands/Checkpoint.tsx:296`
- **What is wrong:** Starting hides the focused summary button, advancing replaces the keyed item containing the focused control, and finishing replaces the quiz with a result, but none of those transitions moves focus.
- **Concrete failure scenario:** In Chromium, focus was `BODY` immediately after activating Start and again after submitting the first answer. A keyboard/screen-reader user is not placed on the new question or result and must rediscover the changed content.
- **Smallest fix:** Give the current question heading and result heading programmatic focus targets (`tabIndex={-1}`) and focus them in effects after start, item advance, and completion; add focus assertions to the checkpoint e2e flow.

#### I6. The required Lighthouse gate is reproducibly red

- **Location:** `lighthouserc.json:15`, `lighthouserc.json:20`
- **What is wrong:** With one run configured, the inherited `lighthouse:no-pwa` assertion fails `forced-reflow-insight` on both localized topic pages. Two complete runs reproduced the same failure, despite all explicit category and transfer-size assertions passing.
- **Concrete failure scenario:** Running the mandated pre-merge command exits 1, so a CI job using this gate rejects the branch.
- **Smallest fix:** Use the Lighthouse traces to remove the topic-page forced synchronous layout, then rerun the exact gate. If this insight is intentionally outside the release contract, explicitly configure that policy instead of relying on an inherited preset assertion.

#### I7. The branch deletes two unrelated P1 review artifacts

- **Location:** `.superpowers/sdd/2026-09-03-p1-site-foundation/design-d1-report.md:1`, `.superpowers/sdd/2026-09-03-p1-site-foundation/task-20-report.md:1`
- **What is wrong:** `git diff --name-status main...HEAD` marks both historical P1 reports deleted; neither deletion belongs to Tasks 1–11 or the P2a sweep.
- **Concrete failure scenario:** Merging the branch removes the prior accessibility-token design report and Mermaid task report from `main`.
- **Smallest fix:** Restore both files unchanged from `main` before merging.

### Minor

#### M1. Suspended overdue cards are still counted as due outside the reviewer

- **Location:** `src/lib/prefs.ts:244`, `src/lib/srs.ts:44`, `src/islands/TodayStrip.tsx:146`
- **What is wrong:** `isDue()` excludes `card.suspended`, but `dueFlashcards()` does not. The home and practice strips use the latter while the flashcard queue uses the former.
- **Concrete failure scenario:** With one overdue suspended card, `/practice/` displays “1 due” and a Review CTA, while `/practice/flashcards/` correctly displays the empty-deck state. This was reproduced in Chromium.
- **Smallest fix:** Exclude suspended cards in `dueFlashcards()` and add a suspended-card unit case.

#### M2. The specified Right Arrow “next kata” shortcut is absent

- **Location:** `src/islands/Quiz.tsx:111`, `src/islands/SpotBug.tsx:120`, `src/islands/ReviewKata.tsx:309`, `src/pages-shared/Kata.astro:252`
- **What is wrong:** The controllers handle number keys and Enter only; no controller or page handler handles `ArrowRight` after completion.
- **Concrete failure scenario:** After answering `predict-loop-binding`, pressing Right Arrow leaves the URL unchanged instead of opening the next kata; this was reproduced in Chromium.
- **Smallest fix:** Add one page-level post-answer Right Arrow handler that follows the next-kata link while ignoring editable controls, and cover it in e2e.

#### M3. `TodayStrip` reimplements the pass threshold

- **Location:** `src/islands/TodayStrip.tsx:81`, `src/lib/score.ts:4`
- **What is wrong:** `passing()` hard-codes `score / total >= 0.7` instead of using the shared `passed()` helper, contrary to the grading single-source constraint.
- **Concrete failure scenario:** Any deliberate change to `PASS_MARK` updates checkpoints and path state but leaves the practice hub selecting checkpoints with the old threshold.
- **Smallest fix:** Import and call `passed(Number(entry.score), Number(entry.total))` after the existing shape checks.

#### M4. Sweep items a/e did not enforce the 60-character title limit

- **Location:** `src/schemas/quiz.ts:17`, `src/lib/practice.ts:116`, `tests/unit/practice.test.ts:127`
- **What is wrong:** Optional titles have no length validation and the fallback truncates to 90 characters; the sweep note required at most 60. The test explicitly locks in 90.
- **Concrete failure scenario:** A 90-character authored title passes the schema and renders unshortened in kata headers and practice cards; a long prompt fallback also remains 90 characters.
- **Smallest fix:** Validate each localized title at 60 characters, truncate fallback output to 60 including the ellipsis, and update the unit test.

#### M5. The new practice reset bypasses the guarded storage helpers

- **Location:** `src/islands/SettingsForm.tsx:269`
- **What is wrong:** The reset path calls `local.removeItem(KEYS.flashcards)` directly instead of expressing the mutation through `prefs.ts`, contrary to the P2 storage constraint.
- **Concrete failure scenario:** A future flashcard migration, notification, or write policy added to the shared helper is bypassed only by Reset practice data, leaving this operation with different semantics from every normal deck write.
- **Smallest fix:** Add a guarded removal helper to `prefs.ts` or write `EMPTY_FLASHCARDS` through `writeStore()` and use it here.

#### M6. Practice duplicates the global `.stat` CSS block

- **Location:** `src/pages-shared/Practice.astro:526`, `src/styles/global.css:2730`
- **What is wrong:** `.stat`, `.stat b`, and `.stat .lbl` repeat the same declarations in component and global CSS.
- **Concrete failure scenario:** Changing the shared stat typography in only one block makes practice and flashcard stats diverge while both still use the same class contract.
- **Smallest fix:** Keep one shared, intentionally scoped global stat block and remove the duplicate component declarations.
