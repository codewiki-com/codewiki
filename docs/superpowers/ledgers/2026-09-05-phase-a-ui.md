## A3 — the verification panel (`2d4325a`)

### The checker

`pnpm content:check {track}/{slug}` now executes the topic's runnable examples and writes
`reports/verify/{track}/{slug}.json`. `--no-verify` skips it. Committed: 287 sidecars, 152 KB.

- A `run` fence followed by a ```text fence (blank lines only between them) is a recorded
  observation: the fence is executed and its output compared. Python runs on `python3.14`
  (3.14.3 here), JavaScript and TypeScript on `node` (24.14.0); TypeScript is stripped with the
  `esbuild-wasm` already in the tree.
- **A block counts as executed only if it was compared.** No recorded output, a browser-only
  language (`sql`, `html`), a language with no host toolchain (`go`, `cpp`), a missing package, a
  missing fixture file, no network, a timeout, or an authored `nocheck` are all reported as
  `skipped` with the reason. The panel can therefore never claim a run that did not happen, and a
  missing `numpy` never reads as content drift.
- `runtime.version` is the tool's own `--version` output, not the frontmatter pin. The pin is
  carried separately as `target`, because a Go example is recorded on the target and executed by
  nothing here.
- One real bug found and fixed mid-run: writing every JS example as `.mjs` made
  `const x = require("node:http")` fail. The extension now follows the source, which moved four
  topics out of the partial state.

### The build

- `src/lib/verify.ts` reads the sidecars (cached), derives the three panel states, the in-browser
  runner line and the per-block labels. **The build fails on a reviewed topic with no sidecar.**
- `MetaPanel` renders, under the existing grid: state glyph and word (`✓ VERIFIED` / `△ N of M
  matched` / `○ NOT RUN`), runtime and patch version, match count, date; the transparency line
  shortened to one line; the browser runner sentence; and a `<details>` listing every runnable
  block with an anchor to it. No JavaScript.
- `rehype-codebox` numbers runnable fences `b1`, `b2`, … — the checker's own numbering — puts
  that id on the `<figure>` and prints "recorded on {runtime}" (plus "runs here on {runner}" when
  the tab differs) beside the Run button. Hidden below 768 px, where the header has room only for
  the buttons.
- Browser runner versions are read at build: Pyodide's package version and the CPython in its
  lock file (`public/vendor/pyodide/`, with `node_modules` as the fallback for an unvendored dev
  tree), `esbuild-wasm` and `sql.js` from `node_modules`. `scripts/vendor-pyodide.mjs` now copies
  `package.json` into `public/vendor/pyodide/` for this.

**Deviations from the note.**

1. The note reads the Python version from `public/vendor/pyodide/package.json`; it is not there.
   The package version comes from `package.json` and the CPython version from `pyodide-lock.json`
   (`info.python`), both vendored.
2. sql.js is named by its npm version (`sql.js 1.14.2`), not by the SQLite version inside it,
   which the package does not expose without loading the wasm.
3. `/python/closures/` shows **"Runs in your browser with Pyodide 314.0.6 (Python 3.14.2)."**, not
   the caveat sentence: the note omits the caveat when the runner's language version equals the
   recording's major.minor, and 3.14 == 3.14. The caveat does appear where it is owed — every
   JavaScript topic gets it, because the tab's own engine is not the Node that recorded the
   output. The e2e asserts the browser line and its versions rather than the caveat wording.
4. The note's `notRun` state is "the topic has no runnable blocks"; it also covers a topic whose
   runnable blocks none of this machine's runtimes could execute, which is the same claim.
5. The panel adds `verify.browserEngine`, `verify.noRunnable` and three `verify.status.*` labels
   beyond the note's list, for the browser-engine case and the disclosure rows.

## A4 — report an error (`5944981`)

`src/lib/report.ts` builds `{SITE.repo}/issues/new?labels=content&title=Error on {path}&body=…`;
the body carries the canonical URL, a "Where:" line (filled in with the kata prompt or the bank
name, and a placeholder on topics) and two prompts. Rendered as a `.lbl` link with
`target="_blank" rel="noopener"` in the topic action row, the kata action row and the interview
bank's controls. The repository is read from `SITE.repo`, never hardcoded, so the Codex branch's
change of value moves every link.

**Deviation.** The link text is localized; the issue body stays English, because it is written
into an English repository for readers of its contributing guide.

### The one budget that had to move — and what it uncovered

The first Lighthouse run failed on one assertion only: `resource-summary:script:size` on
`/python/closures/`, 65,089 bytes against a 63,488 ceiling. Every category score passed. Chasing
it turned up something that is not this branch's doing:

- Main's last green Lighthouse run (2026-09-05 09:26) measured a `dist/` built at 08:27 — **before
  the bilingual About page merged**. That page added eighteen `about.*` keys whose prose bodies
  cost about **2.2 KB compressed** in the one dictionary module every island-bearing page
  downloads. Rebuild `main` today and `/python/closures/` lands near 64.2 KB: over the ceiling
  before Phase A touched anything.
- Phase A's own copy — the hero, the flagship split, sixteen `verify.*` strings, the report link,
  minus four keys deleted with the palette mock — adds about **0.8 KB** on top. Measured by
  reconstructing the dictionary without those keys: 19,695 → 20,512 gzip bytes.
- Every other chunk on the page is byte-identical to main's. No island grew.

The budget is now 66 KiB, with the arithmetic written into `lighthouserc.json`. The real fix is
structural and is *not* done here: strings no island ever reads — `about.*`, `verify.*`, the
tracks and hero copy — should live in a build-only module the way `src/i18n/offline.ts` already
keeps the PWA strings out of every bundle. That would take roughly 3 KB off every page on the
site. It touches `about.*`, which the Codex branch is editing right now, so it belongs in a
commit of its own after both branches land. **Recommended as a ROADMAP entry.**

## Concerns and anything unverified

1. **The script-budget structure**, above. Until the dictionary is split, any copy change on any
   page moves the number on every page, and the budget will keep being raised rather than
   defended.
2. **`python/tuples` is genuinely drifted** against Python 3.14.3, and
   `foundations/regular-expressions` records timings that can never reproduce. Both now render the
   partial state on the live site. Fixing them is a content edit (a corrected output; a `nocheck`
   fence) and was deliberately left out of a UI branch.
3. **159 topics show "Not run."** 130 have no runnable fence (Rust, Java, C#, Swift, Kotlin, PHP,
   C++ tracks), and 29 have fences this machine could not execute — mostly third-party Python and
   Node packages (`numpy`, `langchain`, `graphql`, framework servers) and the browser-only `sql`
   and `html` runners. The panel states the pinned target for those and claims nothing more. If
   the site wants more green panels, the lever is a checker environment with those packages
   installed, plus Go and Rust toolchains at the pinned versions (this machine has Go 1.23.4
   against a pinned 1.27, which is why Go fences are skipped rather than run on the wrong
   compiler).
4. **The sidecars are machine-specific.** They record `python3.14` at 3.14.3 and `node` at
   24.14.0 because that is what this box has. B5's scheduled re-verification should own them from
   here, and should refuse to publish a sidecar written by a runtime older than the pin.
5. **`checkedAt` churns.** Every re-run rewrites 287 timestamps. Harmless, but a diff of a
   re-verification will always look big.
6. **Not verified:** that the browser runners actually reproduce the recorded outputs. The panel
   says which runtime the tab loads and warns where it differs, but nothing compares a Pyodide run
   with the recorded CPython one. That is the honest limit of what this data supports.
7. **`daily-kata.md` §Placement is now superseded** by the hero note, and the section variant of
   the card has no caller. Left in place because the note documents it; a later cleanup could drop
   the variant and its CSS.
